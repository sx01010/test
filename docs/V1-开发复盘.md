# V1 开发复盘：设计取舍、踩过的坑与解决

记录时间：2026-09-21。这是阶段性复盘，不是收尾总结——V1 规格里资料模块、批量导入（R19）、纠错回溯重判（R18）都还没做。

## 一、现在到哪了

已跑通并有测试覆盖的：注册登录与令牌轮换、账号锁定、题库检索与详情、五种客观题判分、错题本与自动掌握、知识点进度、相似题推荐、解析可见性闸门、题目纠错工单、管理端录入与发布（R16–R17）。前端是 Spring Boot 直接发出去的单页，一个进程跑通整套闭环。

本地 MySQL 8.0.46 与 Redis 7.0.15 装在 WSL2，六个 MySQL 迁移脚本已在真实 MySQL 上验证，建出 14 张表零报错。这一步的价值不在"装上了"，而在于**那些 MySQL 专属语法第一次离开 H2 得到验证**：ngram 全文索引、JSON 列、生成列加唯一索引，这三样在 H2 上根本没执行过。

**登录态活过重启**已落到默认 profile：H2 从内存改成 `./data/mathematics` 落盘；集成测试各自钉回内存库，避免精确条数断言被污染。MySQL profile 的 JDBC 字符集参数、种子脚本、WSL 监听配置都改过了，但 **Windows → WSL MySQL 的连通性仍被本机代理/NAT 挡住**，应用层闭环还没在真 MySQL 上跑通。

管理端录入与发布的后端与前端，是在命令执行链路一度不可用的情况下写完的。重启 Cursor 后首次 `mvn -o -B test` 一次通过。这不值得庆祝，只说明"改动面压到最小、贴着既有模式写"这个应对策略在这次奏效了；下一次未必。

## 二、关键设计取舍

每条都写清"不这么定会怎样"，因为取舍的价值在被否掉的那个方案里。

### 答案不进任何列表接口，靠类型结构保证而不是靠纪律

`ProblemRows`（数据库行）有 `answerJson`，`ProblemDtos`（对外 DTO）里根本没有这个字段。想把答案顺着列表接口漏出去，得先改类型定义。

换成一个共用对象加序列化忽略注解也能实现，但那种方案的正确性依赖"每个人都记得加注解"，加一个字段就多一次泄题机会。

### 多空题只暴露空数，不暴露答案

前端要知道渲染几个输入框，所以 `ProblemDetail.blankCount` 会返回。这是答案的**长度**而不是答案本身，不构成泄题；判断标准是"知道这个数能不能提高猜对概率"，答案有几个空提高不了。

### 版本快照：只有内容真变了才升版

`problem` 存题目头（标题、题型、难度、年级、状态），`problem_version` 存内容快照（题干、选项、答案、解析、判题配置、满分）。改标题不升版，改题干才升版。

这不是为了省行数。`submission` 记着作答时的 `problem_version_id`，错题本和提交记录靠它算 `versionChanged`，向学生显示"这道题已更新，当时做的是旧版本"。无脑升版会把所有历史提交都标成已更新，那个提示直接失效。内容比对用 `JsonNode.equals`（对象键顺序不影响判断）而不是比字符串，避免序列化空白差异造成假变更。

已发布题改内容强制填 `changeNote`：改了线上题却不说为什么，后面回溯纠错就没线索。

### 录入时的答案校验复用判题器，不另写规则

把标准答案当成用户答案喂给对应 grader 跑一遍，判不出全对就拒绝入库。多空题的标准答案每空是一组可接受写法，取每空第一个写法拼成用户答案再自检。

录入最容易出的事故是答案 JSON 写成判题器读不懂的形状——保存时风平浪静，学生作答时判题抛异常。另写一套格式校验也能挡住，但两套规则一定会漂移：判题器以后改了容差或空序策略，校验规则不会跟着变。同源校验没有这个问题。

### 来源闸门只在发布时生效

`origin_type` 决定发布前还要补哪个字段（ADAPTED 要改编说明、LICENSED 要授权凭证、PUBLIC 要来源链接），草稿阶段只校验 `origin_type` 本身合法。

合规要求是"不齐不能发布"，不是"不齐不能存草稿"。先录内容、后补授权是真实的工作顺序，草稿阶段就卡住会逼着人在正式字段里填占位符，那比欠着更糟。

`publish=false` 不会把已发布的题降回草稿——下线该是独立动作，不能靠"忘记勾选"触发。

### 跨模块查询放在哪

解析可见性闸门要判断"这道题有没有提交过"，这是一次从 problem 模块读 submission 表的纯查询。放进 `ProblemRepository.hasSubmission`，而不是让 problem 依赖 practice 的 service，两个包因此不会互相依赖。

### 幂等键由前端生成，语义是"同一次作答"

进入题目时生成 UUID，网络重试复用，点"重新作答"换新值。这条语义决定了重做被判成新的一次提交而不是覆盖前一次——统计正确率时这是对的。

### 两套主题的对错配色必须各留在自己色系内

固定的绿对红错在这两套主题里都不好看。中途试过"暖主题借靛蓝表示正确、冷主题借琥珀表示错误"，被打回："这种色调是乱套的，感觉很混乱。"

最终方案：暖主题用橄榄苔绿对、赭红错（都在大地色系内），冷主题用松青绿对、莓红错（都在冷色系内）。跨色系借色会让界面看起来像两套皮肤混在一起。所有实心色对白字保持 4.5:1 以上，文字色对浅底 5.8:1 以上；同时结果标题保留"回答正确/回答错误"文字、选项保留 ✓/✗，颜色不作为唯一信息载体。

### 不引入依赖

没有 Spring Security 过滤器链：鉴权在 `CurrentUserArgumentResolver` 里按接口显式要求，为 6 个匿名接口写一堆放行规则不值得。前端没有表单库、图标库、颜色库，Markdown 渲染自己写了十几行（只支持粗体、段落、无序列表），公式交给 KaTeX。图标是内联 SVG，跟着 CSS 变量换色。

## 三、坑与解决：数据库与测试

### H2 把所有带默认值的列都算成生成键

`GeneratedKeyHolder.getKey()` 抛"期望单个键"异常。根因是 H2 会把 `created_at` 这类带 `DEFAULT CURRENT_TIMESTAMP` 的列也算进生成键。

解决：`connection.prepareStatement(sql, new String[]{"id"})` 显式只声明 id。`UserRepository`、`SubmissionRepository`、`FeedbackRepository` 三处都要改，管理端新写的两个 insert 也沿用这个模式。

### 登录失败计数被事务回滚，账号永远锁不上

`login` 方法带 `@Transactional`，密码错时抛 `ApiException`，Spring 默认对 RuntimeException 回滚——`fail_count` 的自增跟着没了，连续错 100 次也锁不上。

解决：`@Transactional(noRollbackFor = ApiException.class)`。

这个坑最有教育意义：单元测试测不出来，只有"连续 5 次失败后锁定"这种集成测试会暴露。业务异常和技术异常在事务语义上不是一回事，凡是"失败时也要留下痕迹"的逻辑都要显式声明不回滚。

### H2 拒绝没有类型的 NULL 参数

`COALESCE(?, col)` 里绑定 Java `null` 会被 H2 拒掉，因为它无法推断参数类型。

解决：`updateProfile` 改成动态拼 SQL，只更新真正传进来的字段。普通的 `INSERT ... VALUES (?)` 或 `SET col = ?` 传 null 没问题——列类型是已知的，问题只出在函数参数位置。

### MockMvc 按 ISO-8859-1 解码静态资源

断言 index.html 里的中文一定挂。静态资源的 Content-Type 不带 charset，MockMvc 就按 ISO-8859-1 解码。

解决：只断言 ASCII 标记（比如 `app.js`），中文正文交给浏览器按 meta charset 渲染。另外 `/` 走 welcome page 是一次 forward，MockMvc 不跟随，正文断言要放在 `/index.html` 上。

### 跨测试类共享同一个 H2 库，断言互相打挂

默认 profile 的 H2 是 `jdbc:h2:mem:mathematics;DB_CLOSE_DELAY=-1`，整个 JVM 生命周期共享。`PracticeFlowIntegrationTest` 里有"SINGLE,MULTI 恰好 2 条""关键词正方形恰好 1 条"这类精确条数断言，管理端测试一发布新题就把它们打挂。

解决：新测试类用 `@SpringBootTest(properties = "spring.datasource.url=jdbc:h2:mem:admin-authoring;...")` 换一个库名，拿到独立的库和独立的 Spring 上下文。代价是多一次上下文启动。

教训：写了精确条数断言，就等于给共享数据库上了锁。要么断言改成"至少包含某条"，要么新增写数据的测试类一律换库。

### H2 与 MySQL 的 schema 差异要在四个地方分别处理

两套迁移脚本按 Flyway 的 `{vendor}` 占位符分目录。具体差异与对策：

| 差异 | MySQL | H2 上怎么办 |
| --- | --- | --- |
| 同一人同题只能一条 OPEN 工单 | 生成列 + 唯一索引兜底 | 只建普通索引，唯一性靠 service 在事务内先查后插，并捕获 `DuplicateKeyException` 回读 |
| 题干关键词搜索 | ngram 全文索引 | 不建；检索统一走 LIKE，两边都能跑，量大之后再切 `MATCH ... AGAINST` |
| JSON 字段 | JSON 列 | CLOB，`setString` / `getString` 两边通用 |
| `updated_at` 自动更新 | `ON UPDATE CURRENT_TIMESTAMP` | 没有这个写法，所以一律在 SQL 里显式 `SET updated_at = CURRENT_TIMESTAMP` |

`problem_source` 的 upsert 同理：不用 MySQL 的 `ON DUPLICATE KEY`，也不用 H2 的 `MERGE`，改成"先 UPDATE 看影响行数，为 0 再 INSERT"，一条逻辑两边通用。

### 重启要重新登录：不是 Redis 的事，是库易失

症状看起来像"登录态没持久化"，第一反应容易是把令牌搬进 Redis。根因其实是默认 profile 用的 `jdbc:h2:mem`——进程一停，`user` 和 `auth_token` 一起没了。令牌是随机串 SHA-256 后入库的，校验时还要再查 `user`；外键把两张表绑在一起，**只把令牌映射搬到 Redis 扛过重启，下一句 `users.findById` 照样 401**。

解决：默认 profile 改成 `jdbc:h2:file:./data/mathematics`，库文件进 `.gitignore`。集成测试（`PracticeFlowIntegrationTest`、`MathematicsApplicationTests`）用 `@SpringBootTest(properties = ...)` 钉回内存库，否则精确条数断言第二次就挂。`LoginSurvivesRestartTest` 在同一个 JVM 里先后起两个上下文指向同一库文件，钉住"旧令牌重启后还能换回用户"。

Redis 在这个项目里真正该上的是令牌校验挡查询、多实例共享登录失败计数——那是性能和横向扩展，不是这个症状的解药。

### MySQL JDBC URL 写了 `characterEncoding=utf8mb4`

`characterEncoding` 要的是 **Java 字符集名**（`UTF-8`），不是 MySQL 的字符集族名。Connector/J 9.x 在解析连接参数时就抛 `UnsupportedEncodingException: utf8mb4`，连 TCP 都建不起来。这个 profile 从写下来那天起就连不上——因为从没真跑过，所以一直没暴露。

解决：改成 `characterEncoding=UTF-8`；时区参数顺手换成 Connector/J 9.x 的正式名 `connectionTimeZone`。库本身仍是 utf8mb4，驱动会把 UTF-8 映射过去。

### MySQL 种子脚本里的 LaTeX 反斜杠

H2 字符串字面量不做反斜杠转义，MySQL 会：`\b` 变退格、`\(` 的反斜杠被吞，公式当场报废。这个坑只在真跑 MySQL 时暴露。

解决：单独写 `db/seed/mysql/V90__seed_dev_content.sql`，公式里的 `\` 写成 `\\`；自增序列用 `AUTO_INCREMENT = n`；保留字加反引号。mysql profile 默认挂上 seed 目录，正式环境用 `FLYWAY_LOCATIONS` 覆盖掉。

### `SpringApplicationBuilder.properties()` 盖不过 `application.yml`

`LoginSurvivesRestartTest` 第一次失败时，日志里 JDBC URL 仍是 `./data/mathematics`，临时目录断言当然找不到文件。根因是 `properties()` 设的是**默认属性**，优先级低于 `application.yml`。

解决：把覆盖项作为 `run("--spring.datasource.url=...", "--server.port=0")` 的命令行参数传入。另：Windows 上 H2 文件 URL 要用正斜杠绝对路径，反斜杠会被当成转义。

## 四、坑与解决：环境与工具链

这部分吃掉的时间不比功能开发少，而且每一个都不是代码问题。

### apt 全部 404，源 IP 是 198.18.0.102

在 WSL Ubuntu 装 MySQL 时所有 `.deb` 都 404。关键线索是那个源 IP——`198.18.0.0/15` 是保留段，典型的 fake-IP，说明 DNS 被 Windows 侧的本地代理（Clash/mihomo 类）劫持，明文 HTTP 被透明拦截。

诊断的转折点：HTTPS 到国内镜像（TUNA、USTC）握手完全正常，没有 TLS 错误。这说明劫持只作用在明文流量上。

解决：把 `/etc/apt/sources.list.d/ubuntu.sources` 的 URI 从 `http://archive.ubuntu.com/ubuntu` 换成 `https://mirrors.ustc.edu.cn/ubuntu/`，一次装成。另外没有 sudo 权限，改走 WSL 的 root 用户。

判断方法值得记住：看到 404 先看**源 IP 落在哪个段**，保留段就不是镜像的问题。

### Maven 中央库走 HTTP 镜像，插件 jar 永远下不齐

`spring-boot:run` 失败：本地缺 `spring-boot-buildpack-platform` / `spring-boot-loader-tools` 的 jar。真正的本地仓库不在 `~/.m2`，而在 `settings.xml` 的 `<localRepository>`（本机是 `D:\Tools\apache-maven-3.9.9\MAVEN—local repository`）。镜像配了两条：排在前面的 `alimaven`（`mirrorOf=central`）是 **HTTP**，后面的 `aliyunmaven`（`mirrorOf=*`）才是 HTTPS——Maven 取第一条匹配，中央仓库流量全走明文，和 apt 那次是同一个拦截。

解决：把 `alimaven` 的 URL 改成 `https://maven.aliyun.com/repository/central`，再 `-U spring-boot:help` 强制越过 `.lastUpdated` 失败标记。两个 jar 一次下齐，`spring-boot:run` 恢复可用。

### WSL2 里 MySQL 绑 `127.0.0.1`，Windows 侧 Connection refused

Windows JVM 连 `127.0.0.1:3306` 直接 RST。MySQL 默认只听回环，WSL2 localhost 转发在本机（有 TUN 代理、NAT 模式）上不可靠。

第一步：drop-in 写 `bind-address = 0.0.0.0`。第一次失败是因为文件名叫 `99-wsl-bind.cnf`——mysqld 按字母序读 include，`99-` 排在 `mysqld.cnf` **前面**，后者的 `127.0.0.1` 后读覆盖前读。改成 `zz-wsl-bind.cnf` 后 `bind_address` 才变成 `0.0.0.0`。

第二步：即便绑了 `0.0.0.0`，Windows → `127.0.0.1:3306` 仍 refused；改指 WSL IP `172.19.192.255` 则变成 **timeout**（包出去没回来）。结论：本机代理/防火墙把 WSL 网段吞了，不是 MySQL 或 JDBC 配置问题。临时决策：**开发登录持久化走 H2 文件模式**；MySQL 应用层闭环等代理给 WSL 网段加绕过后再验。冒烟测试 `MySqlProfileSmokeTest` 已写好，靠 `DB_PASSWORD` 环境变量门控，没配就不跑。

### PowerShell 把 `<` 当成重定向符

`git commit` 时 Cursor 自动追加的 `--trailer "Co-authored-by: Cursor <cursoragent@cursor.com>"`，尖括号被 PowerShell 解析成重定向操作符，提交直接报错。

解决：用 `git add -A; git commit -m "..."`，不套 `cmd.exe /c "..."` 再嵌一层引号。

### `wsl -l -q` 的输出重定向后全是 NUL 字节

WSL 输出 UTF-16LE，经 PowerShell 管道再落盘按 GBK 转，文件变成不可读的二进制。

解决：把重定向放到 **WSL 内部**（`wsl -- sh -c '... > /mnt/d/...'`），由 Linux 侧直接写成干净 UTF-8，完全绕开 PowerShell 的编码转换。

### 复杂 shell 逻辑内联进 `wsl -- sh -c` 会被撕碎

`$f` 变量展开和转义引号被 PowerShell 抢先处理，到了 WSL 里已经是语法错误。

解决：逻辑落成独立的 `.sh` 文件，调用简化成 `sh -c "tr -d '\r' < /mnt/d/.../setup.sh > /tmp/setup.sh; sh /tmp/setup.sh"`。`tr -d '\r'` 是必须的，Windows 侧写出的 CRLF 会让 bash 报语法错误。

附带一个坑：`target/` 在 gitignore 里，子代理用 glob 找不到就以为目录不存在——gitignore 影响的是搜索工具的可见性，不代表文件不在。

### 命令执行失败：一个症状下面其实有三个原因

一整晚的"命令跑不了"最后拆出三件独立的事。混在一起看的时候完全无法定位，因为**它们的表面症状一模一样**：退出码 1，加一屏乱码。

**第一件：沙箱后端在这台机器上不存在。** 报错原文是 `this machine cannot enforce the 'workspace_readwrite' sandbox policy`——Windows 上的沙箱助手只提供网络代理，没有文件系统隔离。这条不是权限被拒，重启也不会好，唯一的办法是让命令不走沙箱。

**第二件：PowerShell 5.1 不支持 `&&`。** 这是最值得记住的一条，因为它差点被当成"环境坏了"。乱码按 GBK 解出来其实是一句人话：

> 标记"&&"不是此版本中的有效语句分隔符。

而且那段乱码里夹着可读的 ASCII 片段，能看见完整的命令文本——**脚本内容根本没坏，坏的是我写的语法**。PowerShell 5.1 比 `&&` 早，只能用 `;`。代价是 `;` 不短路，所以多步操作要么拆成多条命令逐条确认，要么别指望前一步失败能自动挡住后一步（我把两个 commit 拆成两次执行，就是怕第一个 commit 失败后 `git add -A` 把所有东西塞进第二个 commit 的消息里）。

**第三件：临时脚本内容真的变成了高熵垃圾。** 这一件是真的，和上面两件无关：不同命令、不同临时文件名，`.ps1` 的乱码内容**字节级完全一致**，同一行号同一位置同一批字符。如果是安全软件逐文件加密，每次密文都该不同；内容一致说明写脚本那条链路本身处于一个固定的坏状态。重启 Cursor 之后新会话恢复正常，但同一个会话跑过一条命令后还会复现——所以实际可用的姿势是**一条命令一个新会话**，子代理天然满足这个条件。

**教训：先把乱码解出来再下结论。** 在 GBK 终端里看 UTF-8 错误信息，任何普通错误都长得像环境崩溃。我因为没有第一时间去读那段乱码里的 ASCII 片段，把一个"语法写错了"当成了"工具链损坏"，代价是一整晚没能编译测试。判据很便宜：乱码里有没有你自己命令的文本？有就是你的命令的问题，没有才是脚本本身的问题。

**代码侧的应对**（在确实跑不了编译器的那段时间里）：把改动面压到最小、尽量新增文件而不改老文件、贴着既有模式写（新的 insert 直接照抄 `UserRepository` 的生成键写法），然后逐行自检返回类型、record 组件个数与顺序、RowMapper 列名、imports、SQL 占位符个数。这次运气不错，首次编译零错误。但自检不能替代编译器，所以当时交付的说法是"代码完成、未验证"，而不是"完成"——这个区分比蒙对了更重要。

## 五、回头看

### 值得保留的

**TDD 在这个项目里真救过场。** 账号锁定那个事务回滚 bug，单元测试和肉眼审查都抓不到，只有"连续 5 次失败后锁定"的集成测试能暴露。

**给人看图，不要给 hex 码。** 配色方案第一次是以色值列表给出的，反馈是"我看不到推荐的色彩"。改成渲染一张四方案对比的 HTML 页面，一次就选定了。任何关于视觉的决定都不要用文字描述来征求意见。

**禁用按钮不说原因是坑。** 发布按钮在来源字段没填齐时不禁用，而是提交后由后端告诉具体缺哪一项。禁用状态只表达"不行"，不表达"为什么不行"，用户只能靠猜。

**表单失败要有可聚焦的错误摘要。** 只弹 toast 对键盘用户和读屏用户等于没有提示。错误区用 `role="alert"` 加 `tabindex="-1"`，提交失败后把焦点移进去。

### 下次要改的

**先分清"是我写错了"还是"环境不让我跑"，两个方向的误判都犯过。** 一边把工具链故障当代码故障查，一边把 `&&` 语法错误当工具链故障。判据是一对的：换一个毫无关联的简单命令（`git --version`）还失败，是环境问题；乱码里能看见自己命令的原文，是自己的问题。

**精确条数断言要么别写，要么换库。** 这类断言在共享内存数据库上是定时炸弹，加一个写数据的测试类就炸。

**Windows + PowerShell + WSL + 安全软件这套组合，任何多层引号的命令都要假定会被撕碎。** 超过一层转义就落成脚本文件执行。中文参数同理：提交信息写进文件用 `git commit -F`，不要靠 `-m` 把中文塞进命令行。

**Spring Boot 属性覆盖分不清优先级会写出假测试。** `SpringApplicationBuilder.properties()` 盖不过 `application.yml`，测试以为钉到了临时库，实际还在写 `./data/`。覆盖数据源必须用命令行参数或明确更高优先级的机制，并在日志里核对实际 JDBC URL。
