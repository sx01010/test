# R21–R23 资料下载、上传发布与下架 · 设计

日期：2026-09-21。对应规格 R21、R22、R23 与接口 A22–A25。

## 要解决的问题

真题与讲义下载在 V1 里是独立的获客入口：不用做题也能来下资料。`material` 与 `material_file` 两张表在 V4 迁移里已经建好，但没有任何代码用它们。

难点不在增删改查，在于**文件不能裸奔**。资料是 PDF，其中一部分是拿到授权才能放出去的真题。一个能被猜到、能被转发、永不过期的下载地址，等于把授权内容公开了。

## 存储：本地磁盘 + 自签 URL

规格原文写的是对象存储签名下载。但这台机器上没有 S3 或 MinIO，pom 里也没有任何存储 SDK，而 Windows 到 WSL 的网络此前已经证实被本机代理挡住，装一个也连不上。

所以 V1 落地成：文件写本地目录，签名 URL 由我们自己用 HMAC-SHA256 签发和校验。这保住了这条需求真正的要害——**地址不可预测、短期失效、下架即失效**——而没有引入一个在当前环境里跑不起来的依赖。

换成 S3 时要改的只有一处：写文件和读文件那两个方法。签名逻辑、闸门、审计都不用动，因为它们本来就不关心字节存在哪。

配置放在 `mathematics.material` 下：`storage-dir`（默认 `./data/materials`）、`download-ttl`（默认 5 分钟）、`upload-ttl`、`max-size-bytes`（30 MB，和库里的 CHECK 约束对齐）、`signing-secret`。

`signing-secret` 不配就在启动时随机生成一把，并打 WARN。**不给硬编码默认值**：一个写在仓库里的签名密钥等于没有签名。随机密钥的代价是重启后旧链接失效，而链接本来只活 5 分钟，这个代价不存在。

## 签名令牌

一个不透明令牌，`base64url(载荷) + "." + base64url(HMAC)`，URL 里就一个 `t` 参数。

载荷是 `用途|objectKey|过期时间戳|附加声明…`。

**用途必须进签名**：下载令牌不能拿来当上传令牌用。少了这一段，一个只能读资料的人就能往存储里写文件。

**上传的声明也进签名**：期望的大小与 sha256 写在载荷里，所以服务端不需要为「待上传」状态建表或建行，也不怕客户端上传时改口径。`material_file.material_id` 是 NOT NULL 外键，资料行还不存在，本来也没法先插一条 PENDING 的文件行——把声明放进令牌顺带绕开了这个矛盾。

校验顺序：先验签，再验过期。反过来的话，一个伪造的令牌会先得到「已过期」这种带信息量的回答。

## 上传（R22）

1. `POST /api/v1/admin/materials/upload-ticket`：校验 mimeType 必须是 `application/pdf`、大小在 1 到 30 MB 之间、sha256 是 64 位十六进制。返回 `objectKey`、`uploadUrl`、`expiresAt`。此时不写库。
2. `POST` 那个 `uploadUrl`，带原始字节：验签 → 实际大小对上声明 → 实际 sha256 对上声明 → 头四个字节是 `%PDF` → 落盘。

`objectKey` 形如 `materials/{年}/{uuid}/{清洗后的文件名}`。uuid 保证不可预测，文件名留在路径里是为了 `original_name` 不用另存一处。清洗掉路径分隔符与 `..`，否则一个构造过的文件名能写到目录外面去。

**扫描**：V1 只有结构校验——是 PDF、大小与摘要和凭证一致。通过就记 `scan_status = CLEAN`。这里的 CLEAN 是「结构上是个 PDF 且和凭证吻合」，不是「无毒」，代码里写清楚，将来接 ClamAV 换掉这一个方法。

不校验扩展名，校验的是魔数。扩展名是客户端说了算的东西，拿它当安全依据没有意义。

## 登记与发布（R22）

`POST /api/v1/admin/materials`：用 `objectKey` 认领一个已经上传好的文件，建 `material` 与 `material_file` 两行。

大小与 sha256 在这里**从磁盘上的文件重新算一遍**，不信客户端第二次报的数。`objectKey` 在库里有唯一索引，重复认领会被挡住。

来源闸门和题目那套一致，只在发布时校验：`LICENSED` 必须有 `licenseRef`，`PUBLIC` 必须有 `sourceUrl`，`OWNED` 不用补。草稿阶段允许先欠着——先上传后补授权是真实的工作顺序。

发布还要求文件 `scan_status = CLEAN`。

## 下载（R21）

`POST /api/v1/materials/{id}/download-url`（要登录）：资料必须是 `PUBLISHED`、文件没被标删除，才签发。返回 5 分钟有效的 URL，并写一条 `MATERIAL_DOWNLOAD` 审计。

`GET /api/v1/materials/download?t=…` 匿名可达。**签名本身就是授权**——浏览器直接跳转下载时不会带 Authorization 头，这个接口要是也要求登录，签名 URL 就没有存在的意义了。

这个接口每次都回查资料状态，不只看签名。所以下架后已经发出去的链接**立即失效**，而不是等 5 分钟。规格允许最多 5 分钟，我们做得更严，因为反正要查库才能拿到文件路径。

OpenAPI 里给这个接口留了 429。V1 不做限流：没有 Redis 令牌桶，在单进程内存里做一个只会在多实例下失效，反而给人一种有防护的错觉。这一条明确留到 V2。

## 下架（R23）

`POST /api/v1/admin/materials/{id}/takedown`。OpenAPI 里没有这个接口，是这次补的，和 R18 补纠错列表接口同一个性质。

状态改 `HIDDEN`，文件行记 `deleted_at`，写审计。改完立刻不再签发新链接，已发出的也立刻失效（上面那条回查）。

`deleted_at` 只是给延迟清理打标记。真正删字节需要一个定时任务，V1 没有调度器，这一步留给运维，库里的标记和审计已经把依据留下了。

## 前端

导航加「资料」一栏，匿名可见——这是获客入口，不该藏在登录后面。

列表按类型、年级、年份筛选，走现有游标翻页。每条一个下载按钮：先换签名 URL，再跳转。未登录时点下载引导去登录，而不是报错。

管理端在现有「管理」视图里加第三个页签「资料」：选文件 → 申请凭证 → 上传 → 填元数据 → 存草稿或发布。上传进度与失败原因用 `role="alert"` 播报。

## 测试

集成测试独立 H2 库名，文件写到 `@TempDir`，不碰开发目录。

覆盖：非管理员拿不到上传凭证；sha256 对不上被拒；不是 PDF 被拒；超过 30 MB 被拒；令牌过期被拒；下载令牌当上传令牌用被拒；令牌改一个字节就失效；草稿不出现在公开列表；`LICENSED` 缺授权凭证不能发布；下架后旧链接立刻失效；下载写审计。
